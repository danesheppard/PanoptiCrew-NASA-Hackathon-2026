# PanoptiCrew Application

A React single-page application for exploring environmental case studies through satellite imagery. The experience moves from the welcome page to a Deck.gl map and then to a Three.js terrain story.

The repository includes five curated demonstration studies. Their narrative and analysis are static content; the application does not fetch live case-study data or provide operational response guidance.

## Requirements

- Node.js supported by Vite 8 (Node.js 20.19+ or 22.12+)
- npm
- Network access to the configured satellite and terrain tile providers

## Run Locally

From this directory:

```sh
npm install
npm run dev
```

Vite prints the local URL when the development server starts. To create and serve a production build:

```sh
npm run build
npm run preview
```

## Configuration

Vite reads client-side variables prefixed with `VITE_`. Set these in `.env.local` in this directory (or configure them in the hosting environment):

| Variable             | Purpose                                                        | Example URL template                                                                            |
| -------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `VITE_SAT_TILES`     | Satellite basemap used by the global map and terrain scene     | `https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}` |
| `VITE_TERRAIN_TILES` | Terrarium-encoded elevation tiles used to build the 3D terrain | `https://s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png`                       |

These URLs are requested by the browser, so they are not secret credentials. Keep the provider's usage terms and attribution requirements in mind when changing tile sources. The global map currently displays Esri imagery attribution in its map view.

## Application Flow

- `src/main.jsx` mounts the React application and global stylesheet.
- `src/App.jsx` owns the current view and selected study. Navigation is local component state; there is no URL router.
- The welcome page starts the map exploration.
- On the global map, a study can be selected from a marker or the selector. The sidebar shows its summary, the layer selector changes the displayed raster, and the map/globe controls change the Deck.gl view.
- Launching a study opens the 3D case-study view. Its Overview, Lead-up, Event, and Takeaway chapters are built from the study record. Use the chapter controls or Left/Right Arrow keys to move through them; Home and End move to the first and last story chapters.
- The case-study view can show a raster overlay, adjust its opacity, animate a GeoJSON replay when provided, and display the study's method, limitations, and sources.

## Data and Assets

`src/data/caseStudies.ts` is the application source for study descriptions, dates, map bounds, layer metadata, chapter copy, legends, charts, and optional replay configuration. The records are static and imported directly by the views.

Each study has two separate image collections:

- `layers` describes rasters available in the global map layer selector. Each entry has a display `name`, an asset `file`, and a `legend`.
- `stages` supplies the Lead-up, Event, and Takeaway story chapters. Each stage has a `type` matching the chapter key, narrative fields, and an `imagery` asset; `chart`, `legend`, `replay`, `actions`, and `camera` are optional.

The Overview chapter is generated by the case-study view and does not need a corresponding stage. Study `coordinates` are `[west, south, east, north]` bounds used by the map and terrain scene. `key_dates` uses the `before`, `event`, and `after` keys.

Legend gradients are arrays of RGB stops, each `[red, green, blue]`. Categorical legends use `type: "categories"` and a `categories` array with an RGB `color` tuple and a text `label` per swatch. Labels and colors should describe the raster that is actually displayed.

Static files are served from `public/` without being imported into JavaScript:

- `public/assets/eventIcons/` contains the marker photographs named by each study's `iconImage`.
- `public/assets/geospatial/caseN/` contains that study's raster imagery, charts, and GeoJSON files. Relative paths in study data resolve from this directory; a path beginning with `/` is treated as an application-root URL.
- `public/assets/` contains shared branding and map artwork.

The corresponding analysis and exported research products live under `../dataScience/data/`. The application reads its static content from `src/data/` and `public/assets/`; update those app files when an analysis export changes. A successful Vite build copies `public/` into `dist/`.

## Source Layout

```text
src/
	App.jsx                         View state and navigation
	data/
		caseStudies.ts                Study content and render metadata
		team.js                       Welcome-page team list
	utilities/
		buildLegend.jsx               Shared gradient/category legend renderer
		utilities.ts                  Geographic helpers
	views/
		LandingPage/                  Welcome view
		GlobalMap.jsx                 Deck.gl map and globe
		CaseStudy.jsx                 Three.js terrain and story chapters

	styles.css                      Global and case-study styles
public/assets/                    Static images and geospatial products
```

## Validation

There is no automated test script in `package.json`. Run `npm run build` to check that the application bundles successfully. `npm run preview` serves that built output locally.
